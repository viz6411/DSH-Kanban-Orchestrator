## 0. Пользовательская задача

1. Управлять общим конвейером досок (столбцы, роли, порядок, источник/вход/завершение, автоматизация) в **одном месте**, с пониманием, что правило применится **ко всем доскам всех воркспейсов**.
2. Понимать, **какая это доска** (какой воркспейс) в трёх местах: вкладка Board в диалоге-сессии, страница Board в сайдбаре, экран настроек.
3. Видеть, что из правила **уже лежит** на текущей доске, а что **будет создано** при сохранении.

Целевой пользователь: человек, ведущий команду/конвейер задач (настраивает один раз), и роли-агенты (только читают доску). Экран настроек — для человека.

## 1. Ключевые решения (кратко)

1. **Идентификатор доски — чип в тулбаре доски** (слева), суффикс вкладки «Board · work» убирается, заголовок над доской не вводится. Обоснование в §3.
2. **Единый экран «Workflow»** — полноэкранная панель (overlay) из трёх секций: Столбцы → Автоматизация → Эта доска. Пункт меню `columnEdit` удаляется, остаётся один пункт (рабочее имя `Workflow`), открывающий этот экран.
3. **Граница «все доски / только эта доска» показана явно**: бейдж объёма в подзаголовке панели и у секций 1–2 («все доски»), отдельная секция 3 с бейджем «только эта доска», кнопка сохранения — «Сохранить для всех досок». Переключатель оркестратора этой доски применяется сразу, мимо Save.
4. **Статус столбца относительно текущей доски** — точка-маркер в строке: заполненная = столбец уже есть на доске, пустая = будет создан при сохранении. Лишние столбцы доски не теряются: показаны muted-строкой под списком.
5. **Загрузка состояния** — один вызов `getPolicy` (уже возвращает и общий policy, и столбцы доски, и effective.enabled) + `roles` + `workspaces`. Сохранение — один `saveColumns`, пер-борд — `setEnabled`.
6. **Ошибки inline, черновик сохраняется**: текст ошибки под секцией, введённые значения не сбрасываются, кнопка «Сохранить» остаётся активной для повтора. Конфликт имён (дубликат) ловится на клиенте до отправки.

### 1.1 Фидбек-правки 2026-11-08 (карточка k1601)

7. **Перестановка порядка — drag&drop мышью** (прямое требование человека; деталь в §2.6). Видимые кнопки ↑ ↓ в строке удаляются; клавиатурная/доступная альтернатива — grip-ручка + Space/Enter + ↑/↓. Прежнее решение «стрелки вместо drag» отменено: подмена явного требования не допускается.
8. **Заголовки над колонками редактора обязательны**: `На доске` · `Столбец` · `Роль команды` · `Шаг конвейера`. Третий контрол получает бытовые подписи значений (`Откуда берём` / `Куда кладём` / `Обычный шаг` / `Готово`) и одну поясняющую строку о разнице source/entry — различие читается без документации (§7.1, §2.2).

## 2. A. Единый экран настроек workflow

### 2.1 Точка входа и поток

1. Тулбар доски → кнопка настроек (существующая) → меню:
   - `Workflow` (единственный пункт настройки конвейера; заменяет `columnEdit` + `orchMenu`)
   - `Метки` (labelEdit — без изменений)
2. Открытие панели → запрос `getPolicy` + `roles` + `workspaces` → заполнение формы.
3. Правка строк/опций → кнопка сохранения становится активной.
4. «Сохранить для всех досок» → `saveColumns` → успех: зелёное сообщение + обновлением доски; ошибка: красный текст, черновик цел.
5. Секция «Эта доска» → переключатель немедленно шлёт `setEnabled`, статус показывается у самого переключателя.
6. Закрытие: X / Esc. При несохранённых изменениях — нижняя полоса подтверждения (§2.5).

Пояснения к строке столбца (слева направо):

- `⠿` — grip-ручка (`kanban-wf-grip`): визуальный affordance переноса; участвует в drag&drop и клавиатурном захвате (§2.6).
- `●` / `◌` — маркер наличия на текущей доске (`kanban-wf-dot`, filled/hollow). Подсказка title: «Уже на доске» / «Будет создан при сохранении».
- Имя — input (≤60 символов, как в хосте). Drag строки не начинается с этого поля.
- Роль — select: пустая опция + реальные роли из `roles` (фильтр `^(team-)?(manager|developer|tester|reviewer|designer|researcher)$`, уже реализован в прототипе). Если у сохранённой роли нет в списке — добавить её option, чтобы не «съело» значение (уже есть в прототипе).
- Шаг конвейера (kind) — select с заголовком `Шаг конвейера`: `Куда кладём` (entry) / `Откуда берём` (source) / `Обычный шаг` (flow) / `Готово` (done). Точные подписи en/ru/zh — §7.1. Drag строки не начинается с этого select.
- `✕` — удаление строки (кнопка `wfRemove`). Видимых кнопок ↑ ↓ в строке больше нет (§2.6, §9).

### 2.3 Что глобально, что локально

| Параметр | Объём | Куда пишется | Когда применяется |
|---|---|---|---|
| Столбцы (имена, порядок, роли, kind) | все доски | `kanban-orch.global.json` | при Save, раскладка по всем воркспейсам |
| WIP / enforceWip / autoPull / pullOrder / stamp / labels / dispatch + модель | все доски | тот же файл | при Save |
| Оркестратор «на этой доске» (enabled) | одна доска | `<ws>/.dsh-kanban-orch.json` | немедленно, мимо Save |

Визуально объём подписан: бейдж `все доски` в head-строке (рядом с заголовком) и в caption секций 1–2; секция 3 — бейдж `только эта доска` + имя воркспейса в caption («Эта доска · work»). Это закрывает требование «как пользователь понимает, что сохранение применится ко всем доскам».

### 2.4 Применённые / отсутствующие столбцы на текущей доске

- Строки правила: маркер `●`/`◌` (§2.2). Хост `saveColumns` уже создаёт недостающие столбцы на всех досках и сохраняет лишние столбцы доски — UI только отражает это.
- Лишние столбцы текущей доски (вне правила): muted-строка в конце секции «Столбцы» с их именами. Кнопки для них нет (решение — см. открытый вопрос 1).
- После Save: success-сообщение содержит число обновлённых досок (`boards.length` из ответа хоста — уже есть в прототипе), и выполняется `reload()` текущей доски → маркеры станут `●`.

### 2.5 Ширина 900px и скролл

- Overlay: `position:fixed; inset:16px; overflow:hidden` (как в прототипе). Внутренний скролл только у `.kanban-wf-body` — двойного скролла нет; при узком окне page-скролла body блокируется (overlay фиксированный).
- `.kanban-wf-row` — grid из 6 треков: `14px (grip) 46px (dot) minmax(120px,1fr) (name) minmax(110px,1fr) (role) minmax(120px,1fr) (step) 28px (delete)`, gap 8px. Над сеткой — строка заголовков `kanban-wf-headrow` с теми же треками: пустой grip, `На доске`, `Столбец`, `Роль команды`, `Шаг конвейера`, пустой delete. При ≤980px media-query строка сворачивается в 2 подобратья: подобрать 1 — grip+dot+имя+✕; подобрать 2 — роль+шаг. Свёрнутая строка остаётся **одним draggable-юнитом** (§2.6).
- Max-width контента 640px центрируется, поэтому 900px — комфортный основной размер; ниже 720px работает media-query.

### 2.6 Drag&drop перестановки строк (обязательное требование человека, k1601)

Перестановка порядка столбцов делается **перетаскиванием строки мышью**. Кнопки ↑ ↓ из видимой строки удаляются (§9); перенос — основной способ, grip+клавиатура — доступная альтернатива тому же действию.

**За что цепляется строка (idle).** Drag source — контейнер строки: её фон, отступы и пустые зоны между контролами, плюс grip-ячейка `⠿`. `pointerdown`/`dragstart` на input, select и ✕ drag не начинают — текстовое редактирование и выбор в select работают как раньше (`draggable=false` на контролах, `stopPropagation` на их pointerdown). `cursor: grab` на фоне строки и grip, `cursor: grabbing` во время переноса.

**Состояния (idle / dragging / over / drop / cancel):**

| Состояние | Класс | Что видит пользователь |
|---|---|---|
| idle | — | обычная строка; grip виден всегда; cursor grab |
| dragging | `.kanban-wf-row.is-dragging` | исходная строка: opacity 0.35, пунктирная рамка 1px `--dsw-alias-border-primary`, контролы неактивны; drag-image — стандартный снимок строки (браузерный, без кастомной картинки) |
| over | `.kanban-wf-dropline` | горизонтальная линия-слот 2px на границе между строками, цвет `--dsw-alias-label-secondary`; в активной позиции сброса — `--dsw-alias-label-primary`, соседние строки раздвигаются на 6px (слот открыт) |
| drop | — | строка вставляется в слот; линия исчезает; порядок в форме обновлён; `dirty=true` |
| cancel | — | порядок прежний, dirty не меняется (сравнение массива порядка) |

**Линия сброса (места).** Валидные границы: перед первой строкой (после caption секции), между любыми соседними строками, после последней строки (перед строкой добавления). Сброс выше первой строки = позиция 1; ниже последней = позиция N. Вне секции «Столбцы» (или вне панели) линия не показывается, событие drop не обрабатывается = cancel.

**Отмена.** Esc во время переноса = cancel; drop вне зоны = cancel; сброс на свою же исходную границу = cancel (порядок не меняется). После drop отмена только через discard-полосу закрытия (§4).

**12 строк.** Drag не создаёт и не удаляет строки — лимит 12 на перенос не влияет, drop всегда валиден; поле добавления по-прежнему скрывается на 12-й строке (`wfMaxColumns`).

**Узкий экран (≤980px).** Свёрнутая строка (2 подборатья, §2.5) — один draggable-юнит: захват за любой его фон вне контролов, grip в первом подборатье; линии сброса рисуются только между юнитами строк, не внутри свёрнутой строки.

**Скринридер.** Один live-region `div.kanban-wf-live` (`aria-live="polite"`, визуально скрыт) в конце секции «Столбцы»: на начало переноса — `{name}: перемещается…`; при смене позиции линии — `{name}: позиция {n} из {N}` (trailing, ≤100мс); на drop — `{name}: перемещено на позицию {n}`; на cancel — `{name}: перемещение отменено` (ключи `wfDragStart` / `wfDragPosition` / `wfDragDrop` / `wfDragCancel`).

**Клавиатурная альтернатива (тот же drag).** Grip — focusable (`tabindex=0`, `role=button`, `aria-label = «Переставить {name}»` (`wfReorder`), видимый focus-ring). Space/Enter — захват (строка в стиле `is-dragging`, линия под grip, `aria-pressed=true`); ↑/↓ — перемещение линии (объявления в live-region); Enter/Space — фиксация (drop); Esc — cancel. Поведение, состояния и dirty-логика идентичны мышиному переносу.

**Связь с Save/dirty.** Drop помечает форму dirty, как любая правка; закрытие с несохранённым порядком показывает discard-полосу (§4). Если строка вернулась на исходную позицию — dirty не появляется. Порядок пишется только через `saveColumns` (массив `columns` в глобальном policy); после Save порядок перечитывается с сервера.

**Рекомендуемая техника реализации.** HTML5 native DnD (`draggable=true` на div строки, `dragover` рисует dropline, `drop` переставляет элемент в local state) — минимальная правка minified-React-компонента; либо pointer-events + sortable-логика. Оба варианта обязаны дать перечисленные состояния; выбор за developer.

## 3. B. Идентификатор доски (чья это доска)

**Решение: чип в тулбаре доски.** Альтернативы отвергнуты:

| Вариант | За | Против | Вердикт |
|---|---|---|---|
| Заголовок над доской | Явный, крупный | Съедает вертикальную строку ради 1 короткой строки; дублирует сайдбар; доска и так занимает всю область | ✗ |
| Хлебные крошки `Board / work` | Показывает контекст | Подразумевает навигацию, которой нет: воркспейс выбирается сайдбаром, а не кликом по крошке | ✗ |
| **Чип в тулбаре** | Тулбар — уже «панель контекста/статуса» в этом плагине (refresh, настройки); ноль вертикального места; всегда на месте | Менее «важный» вид | ✓ |

### 3.1 Поведение чипа

- Позиция: **первый элемент тулбара**, слева от refresh. Заменяет теперешнюю plain-подпись `span.kanban-toolbar-board-name` (тот же элемент переоформляется в чип, класс переиспользуется, добавляется новый стиль).
- Стиль: `kanban-toolbar-board-name` → фон `--dsw-alias-fill-tertiary`, радиус 6px, паддинг 3px 8px, шрифт 12px `--dsw-font-xxs-12`, цвет `--dsw-alias-label-secondary`. Не кнопка, не кликабельный.
- Обрезка: `max-width: 160px; overflow:hidden; text-overflow:ellipsis; white-space:nowrap` + `title="<полное имя>"`. Имя = `workspace.title` (fallback `workspace.path`, как уже делает клиент через `window.__kanbanWsTitle`).
- До загрузки данных: чип показывает skeleton-полосу шириной 80px (не «пусто», чтобы не прыгала вёрстка). Чип не должен появляться/исчезать — только менять содержимое.

### 3.2 Три места — один принцип

| Место | Что показываем | Текст |
|---|---|---|
| Вкладка Board в диалоге-сессии | Только статичное имя вкладки | `Board` (en), `Доска` (ru), `看板` (zh) — **без суффикса воркспейса**; суффикс «· work» удалить (источник прыжков и «случайной подписи») |
| Страница Board в сайдбаре | Существующий селектор `kanban-page-select` с label «Workspace» | без изменений (это единственный редактор выбора воркспейса) |
| Экран настроек Workflow | caption секции 3: `Эта доска · <имя воркспейса>` | обрезка как у чипа, `title` с полным именем |

Обоснование для вкладки: вкладки должны быть стабильны по ширине и тексту (они участвуют в layout tabs и появляются до загрузки данных). Идентичность конкретной доски показывает контент (чип тулбара), а не имя вкладки.

| Состояние | Что видит пользователь | Тексты (ru) |
|---|---|---|
| Загрузка столбцов | Skeleton-строки (3 строки-заглушки) вместо таблицы | `Загрузка…` (key `loading`, уже есть) |
| Успешное сохранение | Зелёная строка в foot, кнопка неактивна до новой правки | `Правило сохранено · досок обновлено: {n}` (`wfSaved`) |
| Идёт сохранение | Кнопка disabled, текст кнопки меняется | `Сохранение…` (`wfSaving`) |
| Ошибка сохранения (хост 4xx/throw) | Красная строка в foot + ошибка в верхней части body; **значения формы сохранены**, кнопка активна | `Не удалось сохранить правило: {detail}` (`wfSaveFailed`) |
| Конфликт имён (дубликат в списке) | Красный текст под секцией «Столбцы»; input-дубликат с красной рамкой; Save блокируется | `Столбец с таким именем уже есть` (`wfDupColumn`) |
| Проверка перед Save (пустой список) | `Save`disabled + красный текст под списком | `Нужен хотя бы один столбец` (`wfColumnsEmpty`) |
| Доска без изменений правила | Все маркеры `●`, muted-строки нет | (никаких текстов — норма) |
| Лишние столбцы на доске | Muted-строка под списком столбцов | `На этой доске есть столбцы вне правила: {names} — они останутся на доске, но не участвуют в автоматизации.` (`wfExtraColumns`) |
| Пустой список правил (новый профиль) | Одна muted-строка вместо таблицы: `Пока нет ни одного столбца` + строка добавления (`wfAdd`) | (`wfColumnsEmpty`) |
| Toggle этой доски: успех | Тихая подпись у переключателя на 3с | `сохранено` (`wfBoardSaved`) |
| Toggle этой доски: ошибка | Красный текст у переключателя | `Не удалось переключить: {detail}` (`wfBoardSaveFailed`) |
| Перетаскивание строки (§2.6) | Исходная строка пунктирная полупрозрачная; линия-слот на границе | текста в UI нет; объявления в live-region: `«{name}» перемещается…` → `«{name}»: позиция {n} из {N}` (`wfDragStart`, `wfDragPosition`) |
| Drop выполнен | Строка на новом месте; активна кнопка сохранения | текста в UI нет; `«{name}»: перемещено на позицию {n}` (`wfDragDrop`, live-region) |
| Отмена drag (Esc / drop вне списка) | Порядок прежний | `«{name}»: перемещение отменено` (`wfDragCancel`, live-region) |
| Закрытие с несохранёнными правками | Foot заменяется полосой: текст + 2 кнопки | `Изменения не сохранены` · [Выйти без сохранения] · [Продолжить редактирование] (`wfDiscardTitle`, `wfDiscard`, `wfKeepEditing`) |
| Нет ролей (roles пуст) | Select ролей показывает только «нет роли» | `— нет роли —` (`wfNoRole`), доп. muted не нужен |

Правила валидации (клиент, до отправки):
- Дубликаты: `title.trim().toLowerCase()` не повторяются; сравнение после trim.
- Пустое имя нового столбца: «Добавить» неактивна.
- Максимум 12 столбцов (хостовый лимит `slice(0,12)`) — после 12-й строки поле добавления скрывается, muted: `Максимум 12 столбцов` (`wfMaxColumns`).
- Drag&drop (§2.6) не участвует в валидации: любая позиция строки валидна, лимит 12 drag не меняет.
- `wipLimit` — integer 1..20 (input number с min/max; значение вне диапазона → ошибка inline `Значение WIP: 1–20` (`wfWipRange`)).
- `kind`: ровно один `entry` и ровно один `source`? — **нет** (хост допускает несколько source/done; entry один: `entryColumnTitle: string|null`). Проверка: если отмечено >1 entry — inline `Точка входа может быть только одна` (`wfOneEntry`). source/done — сколько угодно.

Отклик на ошибки хоста: текст `error` из JSON (`the shared column policy could not be saved: ...`, `the workflow needs at least one column`) выводится как `detail` после локализованной префикс-строки; сырой английский допустим как technical detail (привычно в этом продукте).

## 5. Компоненты и реестр взаимодействий

- **Панель**: overlay `.kanban-wf` (прототип) — head / body / foot, `role="dialog"`, `aria-modal`, `aria-label = t('wfTitle')`. Esc закрывает (с учётом dirty-полосы).
- **Строка столбца**: grid `.kanban-wf-row` (треки §2.5): grip `kanban-wf-grip` (шесть точек `⠿`, `color: var(--dsw-alias-label-secondary)`, grip-поведение §2.6), маркер `kanban-wf-dot` (10px круг: filled `--dsw-alias-label-primary`, hollow — border 2px `--dsw-alias-border-primary`), input имени, select роли, select шага, кнопка ✕ `wfRemove` (существующая `kanban-toolbar-button` variant ghost size icon, `title`-подсказка). Видимых ↑ ↓ кнопок нет.
- **Строка заголовков**: `kanban-wf-headrow` — тот же grid, шрифт `--dsw-font-xxs-12` 11–12px, цвет `--dsw-alias-label-secondary`, пустые ячейки над grip и ✕; значения: `wfColOnBoard`, `wfColName`, `wfColRole`, `wfColStep` (§7.1). Sticky внутри `kanban-wf-body` не требуется (список ≤12 строк).
- **Линия сброса**: `kanban-wf-dropline` — 2px, `border-radius:2px`, цвета §2.6; рисуется абсолютным элементом поверх сетки списка (не влияет на треки).
- **Live-region**: `kanban-wf-live` (`aria-live="polite"`, визуально скрыт, в конце секции «Столбцы»).
- **Select роли / kind**: существующий паттерн `kanban-orch-select` из CSS плагина.
- **Чекбоксы автоматизации**: в прототипе нативные checkbox — оставить (просто, доступно). Опционально заменить на DSH switch — **не обязательно**, минимальное изменение предпочтительнее.
- **Кнопка сохранения**: `kanban-toolbar-button` с текстом `Сохранить для всех досок` (`wfSaveAll`) вместо короткого «Сохранить» — это осознанное изменение текста ради ясности объёма действия.
- **Бейдж объёма**: маленький span `.kanban-wf-scope` («все доски» / «только эта доска»), фон `--dsw-alias-fill-secondary`, цвет secondary.
- **Чип воркспейса** (§3.1) — переиспользование `span.kanban-toolbar-board-name` с новым стилем.
- **Данные**: `getPolicy` (shared.sharedTitles.columns/roles/kinds + boardColumns + effective.enabled), `workspaces` (число досок), `roles` (роль-фильтр). Маппинг `boardColumns` на строки правила — по trim-имени (хост `saveColumns` тоже работает по имени).

Порядок секций (зафиксирован): 1 Столбцы → 2 Автоматизация → 3 Эта доска. Обоснование: первичная задача — форма конвейера; автоматизация вторична; per-board переключатель — редко используемый, внизу.

## 9. Что удалить из текущего UI

1. Меню настроек: пункт `columnEdit` (+ весь старый редактор столбцов и его ключи). Остаются: `Workflow` (открывает единую панель) и `Метки`.

3. Суффикс воркспейса во вкладке Board (`Board · work`) → статичное имя вкладки.
4. Старый диалог «Workflow automation» (orchMenu-панель с enabled/source/done/entry/WIP/pullOrder/stamp/labels/dispatch) целиком заменяется новой панелью; его контролы переезжают в секции 1–3 без изменения семантики API.
5. Кнопки ↑ ↓ в строках столбцов — удаляются из видимого UI (реализация 4eb4eb1). Перестановка — drag&drop (§2.6); клавиатурная альтернатива — grip + Space/Enter + ↑/↓. ✕ остаётся.
6. Подпись секции «Order defines the flow. Roles bind columns to team roles.» (4eb4eb1) — заменяется двумя строками: `wfDragHint` (как переставлять) + `wfStepExplain` (чем Source отличается от Entry). Над колонками добавляется строка заголовков `kanban-wf-headrow`.

## 10. Acceptance (для developer / tester)

1. Открытие панели: один раунд `getPolicy`+`roles`+`workspaces`; skeleton до ответа; при ошибке загрузки — `wfSaveFailed`-стиль ошибки с кнопкой «Повторить» (`wfRetry` = `Повторить` / `Retry` / `重试`).
2. Save вызывает `saveColumns` ровно один раз; ответ `boards.length` попадает в `wfSaved`. После успеха current board перезагружается, все маркеры `●`.
3. Toggle секции 3 вызывает `setEnabled` немедленно и не трогает глобальный policy (проверка: после toggle файл `kanban-orch.global.json` не меняется).
4. Дубликат имени: Save заблокирован, ошибка под списком, отправки нет (нет запроса к `/api/kanban-orch`).
5. >1 entry: Save заблокирован с `wfOneEntry`.
6. >12 столбцов: поле добавления скрыто, `wfMaxColumns`.
7. Width 900px: один внутренний скролл (body панели); горизонтального скролла нет.
8. Вкладка Board: текст вкладки не меняется после загрузки данных (e2e-проверка: DOM-текст вкладки постоянен).

## 11. Открытые вопросы (≤3)

1. **Лишние столбцы доски**: сейчас решение — только informational muted-строка, без кнопки «включить в правило». Нужен ли affordance добавления существующего столбца в общий policy (одним кликом)? Пока **нет** (минимальный экран), ждём подтверждения продукта.
2. **Модель для dispatch**: хост хранит `dispatchModel {provider, model}`; есть ли API со списком моделей профиля? Прототип вводит строку `provider/model` вручную. Если API-списка нет — оставить текстовый input; если есть — заменить на `select` (ключ `wfDispatchModel`).
3. **Вход в панель из сайдбара**: нужна ли кнопка настроек workflow на странице Board в сайдбаре, или единственный вход — через меню тулбара самой доски? Решение по умолчанию: единственный вход из тулбара доски (один источник действий), подтверждение продукта требуется.
